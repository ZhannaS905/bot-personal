# Источник календарных опросов Training Test

При TRAINING_TEST_CALENDAR_POLLS_ENABLED=true календарный адаптер читает только
trainers/{OWNER_UID}.groupScheduleV1.workouts через существующий calendarStore.read.
Он не читает states/main.workouts, trainers.workouts и не разрешает schedule.links.
Данные старого календаря и Firestore rules не изменяются.

calendarPlan, findById, обработка callback и обновление опубликованных опросов
используют один адаптер createTrainingCalendar. Поиск идёт по стабильному ID;
перенос даты/времени не меняет ключ опроса. Отменённое занятие исключается из
плана публикации, но доступно findById для отмены существующего сообщения.
Дополнительные занятия берутся из того же массива workouts; принадлежность
к периоду не обязательна. Занятия, существующие только в старых links или main,
не включаются и не мигрируются автоматически.

Если нового массива нет или он невалиден, адаптер завершает операцию с безопасным
фиксированным кодом. Подстановки старого календаря нет. Дубликат ID в новом массиве
отклоняется. Различия со старым календарём не сравниваются и не могут вызывать
COMBINED_CALENDAR_CONFLICT в календарном режиме.

Существующие createCalendar, createGroupCalendar и createCombinedCalendar
сохранены для других потребителей; прежняя композиция вне календарного режима
не изменена. Не менялись запись голосов, MAX API, MID/UUID, двухкнопочная клавиатура,
защита от повторной публикации, автопостинг, автоудаление и проверка раз в 5 минут.

Адресные тесты: 18/18. Полный локальный набор вместе с сохранёнными локальными
диагностическими тестами: 434 теста, 433 прошли, 0 ошибок, 1 пропущен (Linux abstract
socket на macOS). Проверены отсутствие чтений старой базы в настоящем prepare,
отсутствие fallback, дополнительные занятия, перенос, отмена/возобновление,
сохранение MID/UUID/голосов, две кнопки, защита от дубликатов и автоудаление.
Прямые облачные записи и живые сценарии голосования для проверки не выполнялись.
